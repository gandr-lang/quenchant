## vendored-page-bindings

`rust.md`, `testing-contracts.md`, `source-workflow.md`, and `ci-local.md` are adopted byte for byte. `baseline.md` and `baseline.sha256` are a coupled, immutable baseline artifact. NEVER edit these copies locally; reconcile a source change and adopt the resulting artifacts together. Historical filenames and external literals retain their spelling; project-owned terminology follows the specification vocabulary.

| Shared site                                | Binding in this workspace                                                                                                                                                                                                                                                                                                                                                                                                 | Why the interpretation matters                                                                                                   |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Rust crate shape and naming                | The umbrella package is `quenchant` and every other member is `quenchant-*`. A member that the umbrella depends on consumes the facade package `quenchant-anodized` under the dependency name `quenchant`. Arithmetic and shape own runtime domains; macro, lint, and gate packages own different analysis boundaries.                                                                                                    | The source's compiler-stage category prefixes are examples, not extra categories to introduce here.                              |
| Type-level specification and absence       | `quenchant-shape::shape::Maybe` owns non-failure absence. `reason_enum!` creates a closed reason site.                                                                                                                                                                                                                                                                                                                    | The container's type does not establish that an arbitrary reason has the correct domain meaning.                                 |
| Nominal and arithmetic boundaries          | `Int` owns machine-integer representations. Standard operators stay safe and strict; only the explicitly selected unprefixed `fast` API is unsafe.                                                                                                                                                                                                                                                                        | Feature-dependent unchecked behavior MUST NOT escape through a permanently safe operator.                                        |
| Executable specification annotation        | `quenchant-anodized` exports `#[quenchant::spec(...)]` from `quenchant-spec-macros`; published instrumentation is optional.                                                                                                                                                                                                                                                                                               | The consumer-side feature selects an interpretation of authored clauses, not whether an obligation exists.                       |
| Disabled instrumentation                   | Default arithmetic and shape builds are `no_std`; the token helper removes the outer annotation and supported bare nested markers.                                                                                                                                                                                                                                                                                        | Removal supplies no checking evidence and does not imply clause preservation in HIR. Ordinary validation remains.                |
| Enforcing interpretation                   | `check:tests` exercises enabled library features with the enforcing host cfg. `check:anodized-enforcing` checks the mode and runs the Dylint package's negative witnesses.                                                                                                                                                                                                                                                | Backend selection and target cfg output alone cannot certify a host macro artifact or its enforcement.                           |
| Verification representation                | The shape extraction example reads authored source and reports its supported and unreached constructs.                                                                                                                                                                                                                                                                                                                    | It is not a general proof-transfer implementation, and no gandr adapter or source-to-proof theorem is claimed here.              |
| Adequacy witnesses                         | `quenchant-gates` inventories runnable tests and resolves witnesses within their package and target. `check:witnesses` selects the root manifest.                                                                                                                                                                                                                                                                         | Name resolution, execution, distinguishing power, and property-class coverage are separate claims.                               |
| Recursive code and layouts                 | The Dylint call graph, ownership graph, and per-item termination grammar enforce different obligations.                                                                                                                                                                                                                                                                                                                   | A finding-free analysis is not a termination proof or a proof of implicit drop behavior.                                         |
| Source workflow producer/consumer examples | This repository builds its own `quenchant-gates` and loads its local `quenchant-dylints` path. No separate workflow-source installation step is used.                                                                                                                                                                                                                                                                     | A tool MUST inspect the named consumer manifest, not the checkout from which it was installed.                                   |
| Pinned build and commands                  | `rust-toolchain.toml`, `mise.toml`, and `.config/mise/tasks/` select the toolchain and commands.                                                                                                                                                                                                                                                                                                                          | Use `mise run check` and `mise exec -- prek run --all-files`; NEVER substitute an ambient toolchain.                             |
| Gate mapping                               | The root gate includes pins, metadata, publication eligibility, private rustdoc, invocation state, enforcement witnesses, tests, bare-metal builds, Miri, Dylint, Clippy, witness resolution, public boundaries, and formatting.                                                                                                                                                                                          | Source-workspace gate names are interpreted through the actual tasks, not introduced as aliases.                                 |
| Dylint working directory                   | Its Clippy and native-test tasks enter `crates/quenchant-dylints`; other workspace checks run at the root.                                                                                                                                                                                                                                                                                                                | Cargo's configuration lookup follows the working directory, not merely a manifest argument.                                      |
| Miri and profiles                          | The `dev` and `test` profiles both keep assertions and overflow checks. Miri enables its matching library cfg through the Miri task environment.                                                                                                                                                                                                                                                                          | A test-only profile setting does not establish the same behavior for the first Miri pass.                                        |
| Publication posture                        | `quenchant-gates publish-allowlist` checks the exact eligible family and refuses publication of fixture macros. Actual publication is manual.                                                                                                                                                                                                                                                                             | Eligibility and dry-run preparation do not establish that a registry release exists.                                             |
| Tooling posture and shell lint             | Repository checks and toolchain edits live in `quenchant-gates`. Tasks and workflow steps are launch lines; directory and environment selection use native task fields. No shell/Python sources or shell lint remain.                                                                                                                                                                                                     | The shared shell-lint row is a source example, not a requirement to retain an interpreter gate after its last source is removed. |
| Hooks and messages                         | `prek.toml` selects the local checks; `commitlint.config.mjs` owns the accepted type/scope vocabulary. The publication page describes typed provenance.                                                                                                                                                                                                                                                                   | NEVER assume that a source-workspace hook or installation mechanism exists here.                                                 |
| CI                                         | Build/test and Dylint are merge-group/main jobs; Clippy, anodized invocation policy, format/policy and zizmor form the PR lane. `QUENCHANT_CI_IMAGE` selects `ghcr.io/gandr-lang/quenchant-ci` through the same repository variable. The Git/JQ path filter keeps failed comparisons fail-open; no script is adopted. Miri remains a local gate; this hosted workflow has no Miri, big-endian or cross-OS lane.           | `ci-local.md` supplies the shared act commands and switch semantics; platform examples do not add coverage.                      |
| Configuration-sensitive CI evidence        | `check:no-std` builds real bare-metal targets. `check:tests` and `check:anodized-enforcing` run enabled instrumentation and deliberately violated postconditions. `dylint:tests`, `dylint:clippy` and `anodized:specifications` select the package directory; `tests:enforcing` and `check:doc` declare compiler environments in task fields.                                                                             | A host macro's cfg listing alone proves no enforcement. A panic from another cause is not an enforcing witness.                  |
| CI reproduction map                        | Rust or public features: `mise run check`; compiler policy: `check:dylint` and `check:tests`; wrapper/backend: `check:tests`, `check:anodized-enforcing`, `check:no-std`; witnesses: `check:witnesses` and gate-package tests; pins/YAML/policy: `check:ci-pins`, `check:action-pins`, `check:public-boundary`, `treefmt:check`. Docs: `mise run treefmt`, then `mise exec -- prek run --all-files` and changed examples. | Run named checks through mise. Root gating does not replace diagnosis of a failed narrow command.                                |

Revisit a binding when its named package, public interface, task, or artifact owner changes. A changed interpretation and its callers land together; a copied page is not patched to conceal drift.
